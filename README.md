# TripMind AI

Gemini AI를 활용하여 사용자의 여행 조건에 맞는 국내 여행지를 추천하는 AI 여행 플래너 서비스입니다.

여행 날짜, 여행 스타일, 동반자, 추가 요청을 분석하여 추천 여행지와 날씨, 관광 정보를 제공합니다.

---

## 1. 프로젝트 소개

여행지를 선택할 때 여행 날짜, 여행 스타일, 동반자에 따라 적합한 여행지가 달라집니다.

TripMind AI는 이러한 정보를 사용자가 직접 입력하면 AI가 조건을 종합적으로 분석하여 적합한 국내 여행지를 추천하도록 구현했습니다.

또한 실제 웹 서비스로 배포하여 별도의 개발 환경 없이 브라우저에서 서비스를 사용할 수 있도록 구성했습니다.

---

## 2. 주요 기능

* 여행 날짜 입력
* 여행 스타일 선택
* 여행 동반자 선택
* 추가 요청 입력
* Gemini AI 기반 국내 여행지 추천
* 여행 시기의 일반적인 날씨 정보 제공
* 추천 행사 및 관광 포인트 제공
* AI 추천 결과를 웹페이지에서 확인
* Vercel을 이용한 실제 웹 서비스 배포

---

## 3. AI 활용

TripMind AI는 **Google Gemini API**를 사용하여 여행지를 추천합니다.

사용자가 입력한 정보를 Python API로 전달하고, Gemini AI가 다음 조건을 종합적으로 고려하여 여행지를 추천합니다.

* 여행 날짜
* 여행 스타일
* 여행 동반자
* 사용자의 추가 요청

Gemini AI는 다음과 같은 JSON 형태의 결과를 생성합니다.

```json
{
  "recommended_city": "추천 국내 여행지",
  "weather": "여행 시기의 일반적인 날씨 설명",
  "events": [
    "추천 행사 또는 관광 포인트 1",
    "추천 행사 또는 관광 포인트 2"
  ],
  "reason": "추천 이유"
}
```

생성된 결과는 다시 웹페이지로 전달되어 사용자가 보기 쉬운 형태로 표시됩니다.

## AI 오류 처리

사용자 입력 오류와 API 오류 상황에 대응하도록 처리했습니다.

- 필수 입력값 누락:
  "여행 정보를 입력해주세요." 안내

- AI API 오류:
  "잠시 후 다시 시도해주세요." 안내

- 응답 지연:
  로딩 메시지를 표시

## 4. 서비스 동작 과정

```text
사용자 여행 정보 입력
        ↓
JavaScript에서 API 요청
        ↓
POST /api/recommend
        ↓
Python Serverless Function
        ↓
Google Gemini API
        ↓
여행지 추천 결과 생성
        ↓
웹페이지에 결과 표시
```

### 화면 상태 처리

사용자의 추천 요청에 따라 다음과 같이 화면 상태가 변경됩니다.

```text
사용자 입력
    ↓
추천 요청
    ↓
로딩 상태 표시 + 추천 버튼 비활성화
    ↓
API 요청
    ↓
┌───────────────┐
│               │
성공            실패
↓               ↓
추천 결과 표시   오류 메시지 표시
```

### 성능 및 비용 고려

Gemini API는 요청마다 AI 연산이 발생하므로 응답 시간과 API 사용량을 고려하여
불필요한 호출을 줄이고 사용자가 응답을 기다리는 동안 현재 상태를 확인할 수 있도록
로딩 상태를 제공합니다.

현재 서비스에서는 다음과 같이 처리합니다.

- 사용자가 추천 요청을 보내는 동안 로딩 메시지를 표시합니다.
- AI 요청 중에는 추천 버튼을 비활성화하여 중복 요청을 방지합니다.
- 응답이 30초 이상 지연되면 timeout을 발생시키고 사용자에게 다시 시도하도록 안내합니다.
- 필요한 경우에만 Gemini API를 호출하도록 구성하여 불필요한 API 사용을 줄입니다.
- 프롬프트에 필요한 정보와 출력 형식을 명확하게 지정하여 불필요하게 긴 응답 생성을 줄입니다.

향후 사용자가 증가하여 API 호출량이 많아질 경우 다음과 같은 방법으로
성능과 비용을 추가로 개선할 수 있습니다.

- 동일한 여행 조건에 대한 AI 결과 캐싱
- 사용자별 또는 IP별 요청 횟수 제한
- 응답에 필요한 범위로 프롬프트와 출력 길이를 제한
- 서비스 규모에 따라 비용 효율적인 경량 AI 모델로 변경
- 자주 사용되는 여행 조건에 대한 사전 생성 결과 활용
- API 사용량과 오류율을 모니터링하여 과도한 호출 방지

현재는 별도의 결과 캐싱을 적용하지 않았으며,
사용자 증가 및 API 사용량에 따라 단계적으로 적용할 수 있도록 확장 가능성을 고려했습니다.

### 확장 설계

현재 TripMind AI는 프론트엔드와 백엔드를 API를 기준으로 분리하여 구성했습니다.

- **Frontend**: 사용자 입력, 화면 구성, 로딩 상태, 오류 메시지, AI 추천 결과 표시를 담당합니다.
- **Backend**: `/api/recommend` API를 통해 입력값을 검증하고 Gemini API를 호출하여 추천 결과를 반환합니다.

이러한 구조를 사용하면 화면을 변경하거나 새로운 기능을 추가할 때
AI API를 직접 수정하지 않고 프론트엔드와 백엔드를 각각 독립적으로 수정할 수 있습니다.
또한 Gemini API Key는 백엔드 환경변수로 관리하기 때문에 프론트엔드 코드에 노출되지 않습니다.

#### 프론트엔드 확장

새로운 화면이나 사용자 기능이 추가될 경우 기존 HTML/CSS/JavaScript 구조를 유지하면서
기능별 화면과 JavaScript 로직을 추가할 수 있습니다.

예를 들어 다음과 같은 기능을 확장할 수 있습니다.

- 여행지 상세 정보 화면
- 추천 결과 저장 및 즐겨찾기
- 여행 일정 생성 화면
- 지도 기반 여행지 위치 표시
- 이전 추천 결과 조회

#### 백엔드 확장

새로운 AI 기능이나 외부 API 연동이 필요한 경우 `api/` 폴더에
기능별 Serverless Function을 추가하는 방식으로 확장할 수 있습니다.

예를 들어 다음과 같이 API를 추가할 수 있습니다.

```text
/api/recommend
    ↓
여행지 추천

/api/itinerary
    ↓
여행 일정 생성

/api/place
    ↓
여행지 상세 정보 조회

/api/favorites
    ↓
추천 결과 저장 및 조회
```

각 API는 프론트엔드와 정해진 요청 및 응답 형식으로 통신하도록 구성하여
기존 `/api/recommend` 기능에 영향을 최소화할 수 있습니다.

#### API 인터페이스 확장 예시

현재 여행 추천 API는 다음과 같은 요청 형식을 사용합니다.

```json
{
  "date": "2026-08-25",
  "style": "자연 / 힐링",
  "companion": "가족",
  "request": "아이들과 함께 즐길 수 있는 여행지를 추천해주세요."
}
```

향후 여행 일정 생성 기능을 추가할 경우 별도의 API를 사용하여 다음과 같이 확장할 수 있습니다.

```json
{
  "destination": "평창",
  "date": "2026-08-25",
  "companion": "가족",
  "days": 2
}
```

이처럼 기능별 API의 입력과 출력을 명확하게 분리하면
새로운 기능을 추가하더라도 기존 여행 추천 기능의 수정 범위를 최소화할 수 있습니다.

현재 프로젝트 규모에서는 단순한 구조를 유지하고,
서비스 기능과 사용자가 증가할 경우 기능별 모듈과 API를 단계적으로 추가하는 방향으로 확장할 수 있습니다.

## 5. 사용 기술

| 구분         | 기술                    |

| Frontend   | HTML, CSS, JavaScript |

### Frontend 기술 역할

- **HTML**: 여행 날짜, 여행 스타일, 동반자, 추가 요청을 입력하고 AI 추천 결과를 표시하는 웹페이지의 구조를 담당합니다.
- **CSS**: 웹페이지의 레이아웃과 디자인을 구성하고 모바일 화면에서도 사용할 수 있도록 반응형 스타일을 적용합니다.
- **JavaScript**: 사용자 입력을 처리하고 `/api/recommend` API에 요청을 보내며, AI 추천 결과와 로딩 및 오류 상태를 화면에 표시합니다.

### 프레임워크 도입 검토

현재 프로젝트는 별도의 프론트엔드 프레임워크 없이 HTML, CSS, JavaScript를 사용하여
구현했습니다. 프로젝트 규모가 크지 않아 별도의 프레임워크 없이도 필요한 기능을 구현할 수
있도록 구성했습니다.

향후 사용자 기능과 화면이 증가할 경우 React와 같은 프론트엔드 프레임워크를 도입할 수 있습니다.

**장점**
- 컴포넌트 단위로 UI를 관리하여 코드 재사용성이 높아집니다.
- 화면 상태와 사용자 입력을 체계적으로 관리할 수 있습니다.
- 기능이 많아질수록 유지보수가 편리해질 수 있습니다.

**단점**
- 프로젝트 구조와 개발 복잡도가 증가할 수 있습니다.
- 별도의 빌드 환경과 패키지 관리가 필요합니다.
- 현재 프로젝트 규모에서는 불필요한 복잡성이 추가될 수 있습니다.

**예상 변경 범위**

React를 도입할 경우 기존 HTML 화면을 React 컴포넌트로 변경하고,
JavaScript의 사용자 입력 및 화면 상태 처리 부분을 React 방식으로 변경해야 합니다.

반면 Python의 `/api/recommend` API와 Gemini API 연동 구조는 그대로 유지할 수 있으므로
백엔드 변경 범위는 최소화할 수 있습니다.

## 7. API 구성

### POST /api/recommend

사용자가 입력한 여행 정보를 전달하면 Gemini AI를 이용하여 국내 여행지를 추천합니다.

### 요청 데이터

```json
{
  "date": "2026-08-25",
  "style": "자연 / 힐링",
  "companion": "가족",
  "request": "아이들과 함께 즐길 수 있는 여행지를 추천해주세요."
}
```

### 실제 AI 응답 예시

배포된 웹 서비스에서 정상적인 여행 정보를 입력하여 Gemini API를 호출한 결과,
다음과 같은 JSON 응답을 확인했습니다.

```json
{
  "recommended_city": "강원특별자치도 평창군",
  "weather": "8월 말의 평창은 해발고도가 높아 여름철에도 비교적 선선하고 쾌적한 기온을 유지하여 야외 활동에 적합합니다.",
  "events": [
    "대관령 삼양목장에서의 드넓은 초원 산책 및 자연 체험",
    "오대산 월정사 전나무 숲길에서의 가족 힐링 산책",
    "발왕산 케이블카 탑승을 통한 백두대간 조망 및 스카이워크 체험"
  ],
  "reason": "평창은 고지대에 위치하여 늦여름에도 가족들과 시원하게 대자연을 만끽할 수 있는 최적의 여행지입니다."
}
```

### 오류 응답

필수 입력값이 누락되거나 API 호출 과정에서 오류가 발생한 경우,
HTTP 상태 코드와 함께 다음과 같은 공통 오류 형식으로 응답합니다.

#### ① 입력값 오류

필수 입력값이 누락된 경우 HTTP `400` 응답을 반환합니다.

```json
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "여행 날짜를 입력해주세요."
  }
}
```

#### ② HTTP 메서드 오류

`POST` 이외의 방식으로 `/api/recommend`에 요청하는 경우
HTTP `405` 응답을 반환합니다.

```json
{
  "error": {
    "code": "METHOD_NOT_ALLOWED",
    "message": "이 API는 POST 요청만 지원합니다."
  }
}
```

#### ③ AI API 오류

Gemini API 호출 또는 서버 처리 과정에서 오류가 발생한 경우 
HTTP `500` 응답을 반환합니다.

```json
{
  "error": {
    "code": "AI_API_ERROR",
    "message": "AI 추천 처리 중 오류가 발생했습니다."
  }
}
```

### API 응답 처리

프론트엔드는 HTTP 상태 코드와 오류 코드에 따라 응답을 처리합니다.

- `200`: AI 추천 결과를 화면에 표시
- `400`: 사용자 입력 오류 안내
- `405`: 잘못된 HTTP 메서드 사용 안내
- `500`: AI 추천 처리 오류 안내

AI 추천 결과가 정상적으로 반환되면 추천 여행지, 날씨,
추천 관광 포인트, 추천 이유를 웹페이지에 표시합니다.

- 추천 여행지와 날씨, 행사 및 관광 포인트, 추천 이유가 화면에 표시되었습니다.

### ② 필수 입력 누락 테스트

여행 날짜, 여행 스타일, 여행 동반자 중 일부 필수 항목을 선택하지 않은 상태에서
추천을 요청했습니다.

**테스트 결과**

- 필수 입력값이 누락된 경우 프론트엔드에서 API 요청을 보내지 않고 입력 안내 메시지를 표시했습니다.
- `"여행 날짜, 스타일, 동반자를 모두 선택해주세요."` 메시지를 확인했습니다.
- 백엔드에서도 필수 입력값이 누락된 경우 HTTP `400`과 `INVALID_INPUT` 오류를 반환하도록 처리했습니다.

### ③ 긴 입력 테스트

추가 요청에 긴 문장을 입력하여 입력 내용이 긴 상황에서도
AI 추천 기능이 정상적으로 동작하는지 확인했습니다.

**테스트 입력**

```text
가족과 함께 국내 여행을 계획하고 있습니다. 자연과 힐링을 중심으로 여행하고 싶으며 아이들도 함께 즐길 수 있는 체험 활동이나 관광지가 있었으면 좋겠습니다. 이동 시간이 너무 길지 않고 가족 단위로 방문하기 좋은 장소를 중심으로 추천해주세요.
```

**테스트 결과**

- 긴 추가 요청이 정상적으로 처리되었습니다.
- Gemini AI가 여행 날짜, 여행 스타일, 동반자 및 추가 요청을 종합하여 여행지를 추천했습니다.
- 추천 여행지와 날씨, 관광 포인트, 추천 이유가 웹페이지에 정상적으로 표시되었습니다.

Gemini API 호출 과정에서 오류가 발생하거나 응답이 지연되는 상황을
가정하여 오류 처리 기능을 테스트했습니다.

**테스트 결과**

## 9. 환경변수 설정

Gemini API Key는 보안을 위해 환경변수로 관리합니다.

로컬 개발 환경에서는 프로젝트 루트에 `.env` 파일을 생성하고
실제 Gemini API Key를 저장합니다.

```text
GEMINI_API_KEY=your_gemini_api_key
```

실제 API Key가 포함된 `.env` 파일은 GitHub에 업로드하지 않습니다.

GitHub 저장소에는 실제 키가 포함되지 않은 .env.example 파일만 제공합니다.

```text
GEMINI_API_KEY=your_gemini_api_key_here
```

.gitignore 파일에 .env를 등록하여 실제 API Key가 저장소에 포함되지 않도록 설정합니다.


### Vercel 환경변수 설정

Vercel에 배포된 Production 환경에서는 프로젝트의
**Settings → Environment Variables**에서 `GEMINI_API_KEY`를 등록합니다.

환경변수는 다음과 같이 설정합니다.

- **Name**: `GEMINI_API_KEY`
- **Value**: 발급받은 Gemini API Key
- **Environment**: `Production`

API Key는 프론트엔드 코드에 직접 작성하지 않고
Vercel 환경변수로 관리하여 브라우저에 노출되지 않도록 구성했습니다.

환경변수를 새로 등록하거나 변경한 경우
변경된 환경변수가 적용되도록 새로운 배포를 진행합니다.

배포가 완료된 후 Production URL에서
AI 여행 추천 기능이 정상적으로 동작하는지 다시 확인합니다.

### API Key 유출 대응

Gemini API Key가 GitHub 저장소, 로그, 화면 캡처 등에 노출된 것으로 의심되는 경우
다음 절차에 따라 대응합니다.

1. 노출된 API Key를 즉시 폐기하거나 비활성화합니다.
2. Google AI Studio에서 새로운 API Key를 발급합니다.
3. Vercel의 **Settings → Environment Variables**에서 기존 API Key를 새로운 키로 교체합니다.
4. 변경된 환경변수가 적용되도록 새로운 배포를 진행합니다.
5. GitHub 커밋과 프로젝트 파일을 확인하여 API Key가 추가로 노출된 곳이 없는지 확인합니다.
6. `.env` 파일이 Git에 포함되지 않았는지 `.gitignore` 설정을 다시 확인합니다.

API Key는 README, 소스 코드, GitHub 커밋, 로그, 화면 캡처 등에
직접 기록하거나 공개하지 않습니다.

## 11. 배포

Vercel을 이용하여 실제 웹 서비스로 배포했습니다.

### Production

[TripMind AI 배포 사이트](https://c-jade-nu.vercel.app)

배포 후 실제 서비스에서 여행 정보를 입력하고 Gemini AI의 여행 추천 결과가
정상적으로 생성되는 것을 확인했습니다.

### 배포 문제 진단 및 재배포

배포 후 웹페이지가 정상적으로 표시되지 않거나 AI 추천 기능에 문제가 발생할 경우,
다음 순서로 원인을 확인합니다.

#### 1. 배포 상태 확인

Vercel 프로젝트의 **Deployments** 메뉴에서 가장 최근 배포의 상태를 확인합니다.

- `Ready`: 배포가 정상적으로 완료된 상태
- `Error`: 빌드 또는 배포 과정에서 오류가 발생한 상태

#### 2. Build Logs 확인

배포 상태가 `Error`인 경우 해당 배포를 선택하여 **Build Logs**를 확인합니다.

패키지 설치 오류, Python 파일 오류, 프로젝트 구조 문제 등
빌드 과정에서 발생한 오류 메시지를 확인하고 코드를 수정합니다.

#### 3. Runtime Logs 확인

웹페이지는 정상적으로 표시되지만 AI 추천 기능이 동작하지 않는 경우
Vercel의 **Runtime Logs**에서 `/api/recommend` 실행 과정의 오류를 확인합니다.

예를 들어 다음과 같은 문제를 확인할 수 있습니다.

- Gemini API 호출 오류
- Python Serverless Function 실행 오류
- 잘못된 요청 데이터
- 환경변수 누락

#### 4. 환경변수 확인

Gemini API 호출 오류가 발생하면 Vercel의

**Settings → Environment Variables**

에서 `GEMINI_API_KEY`가 등록되어 있는지 확인합니다.

API Key 자체는 로그나 화면에 출력하지 않고,
환경변수의 존재 여부와 적용 환경만 확인합니다.

#### 5. 코드 수정 및 GitHub Push

오류 원인을 확인한 후 로컬 코드에서 문제를 수정합니다.

수정한 코드는 GitHub 저장소에 커밋하고 push합니다.

```bash
git add .
git commit -m "fix: 배포 오류 수정"
git push
```
GitHub와 Vercel이 연결되어 있으므로 새로운 커밋이 push되면
새로운 배포가 자동으로 진행됩니다.

필요한 경우 Vercel의 Deployments → 해당 배포 → Redeploy를 이용하여
수동으로 다시 배포할 수 있습니다.

#### 6. 배포 후 재검증

새로운 배포가 완료되면 Production URL에 접속하여
다음 항목이 정상적으로 동작하는지 다시 확인합니다.

- 메뉴 및 페이지 이동
- 여행 정보 입력
- 필수 입력값 누락 시 오류 메시지
- AI 추천 요청
- AI 추천 결과 표시
- API 오류 발생 시 오류 메시지
- AI 응답 지연 시 안내 메시지
- 모바일 화면 표시

모든 기능이 정상적으로 동작하는 것을 확인한 후
최종 Production URL을 제출합니다.

#### 7. 배포 문제 확인 흐름

```text
사용자에게 문제 발생
        ↓
Vercel Deployments 확인
        ↓
    빌드 문제인가?
      ↙      ↘
    YES       NO
     ↓         ↓
Build Logs   Runtime Logs 확인
확인           ↓
     ↓      API/환경변수 확인
코드 수정       ↓
      ↘       ↙
       GitHub Push
           ↓
       Vercel 재배포
           ↓
     Production 재검증
```
