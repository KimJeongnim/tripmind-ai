# TripMind AI

Gemini AI를 활용하여 사용자의 여행 조건에 맞는 국내 여행지를 추천하는 AI 여행 플래너 서비스입니다.

여행 날짜, 여행 스타일, 동반자, 추가 요청을 분석하여 추천 여행지와 날씨, 관광 정보를 제공합니다.

---

## 1. 프로젝트 소개

여행지를 선택할 때 여행 날짜, 여행 스타일, 동반자에 따라 적합한 여행지가 달라집니다.

TripMind AI는 이러한 정보를 사용자가 직접 입력하면 AI가 조건을 종합적으로 분석하여 적합한 국내 여행지를 추천하도록 구현했습니다.

또한 실제 웹 서비스로 배포하여 별도의 개발 환경 없이 브라우저에서 서비스를 사용할 수 있도록 구성했습니다.

---

## 2. 주요 기능

* 여행 날짜 입력
* 여행 스타일 선택
* 여행 동반자 선택
* 추가 요청 입력
* Gemini AI 기반 국내 여행지 추천
* 여행 시기의 일반적인 날씨 정보 제공
* 추천 행사 및 관광 포인트 제공
* AI 추천 결과를 웹페이지에서 확인
* Vercel을 이용한 실제 웹 서비스 배포

---

## 3. AI 활용

TripMind AI는 **Google Gemini API**를 사용하여 여행지를 추천합니다.

사용자가 입력한 정보를 Python API로 전달하고, Gemini AI가 다음 조건을 종합적으로 고려하여 여행지를 추천합니다.

* 여행 날짜
* 여행 스타일
* 여행 동반자
* 사용자의 추가 요청

Gemini AI는 다음과 같은 JSON 형태의 결과를 생성합니다.

```json
{
  "recommended_city": "추천 국내 여행지",
  "weather": "여행 시기의 일반적인 날씨 설명",
  "events": [
    "추천 행사 또는 관광 포인트 1",
    "추천 행사 또는 관광 포인트 2"
  ],
  "reason": "추천 이유"
}
```

생성된 결과는 다시 웹페이지로 전달되어 사용자가 보기 쉬운 형태로 표시됩니다.

## AI 오류 처리

사용자 입력 오류와 API 오류 상황에 대응하도록 처리했습니다.

- 필수 입력값 누락:
  "여행 정보를 입력해주세요." 안내

- AI API 오류:
  "잠시 후 다시 시도해주세요." 안내

- 응답 지연:
  로딩 메시지를 표시

## 4. 서비스 동작 과정

```text
사용자 여행 정보 입력
        ↓
JavaScript에서 API 요청
        ↓
POST /api/recommend
        ↓
Python Serverless Function
        ↓
Google Gemini API
        ↓
여행지 추천 결과 생성
        ↓
웹페이지에 결과 표시
```

### 화면 상태 처리

사용자의 추천 요청에 따라 다음과 같이 화면 상태가 변경됩니다.

```text
사용자 입력
    ↓
추천 요청
    ↓
로딩 상태 표시 + 추천 버튼 비활성화
    ↓
API 요청
    ↓
┌───────────────┐
│               │
성공            실패
↓               ↓
추천 결과 표시   오류 메시지 표시
```

### 성능 및 비용 고려

Gemini API 호출 과정에서 발생할 수 있는 응답 지연과 API 사용량을 고려하여
사용자에게 로딩 상태를 표시하고, 추천 요청 시 필요한 경우에만 API를 호출하도록 구성했습니다.

향후 사용량이 증가할 경우 다음과 같은 방법으로 성능과 비용을 개선할 수 있습니다.

- 동일하거나 유사한 요청에 대한 결과 캐싱
- 요청 횟수 제한을 통한 불필요한 API 호출 방지
- 응답에 필요한 범위로 프롬프트를 간결하게 구성하여 토큰 사용량 절감
- 서비스 규모에 따라 경량 AI 모델 사용 검토
- AI 응답이 지나치게 지연될 경우 timeout 처리 적용

### 확장 설계

현재 프론트엔드와 백엔드는 API를 기준으로 역할을 분리하여 구성했습니다.

- **Frontend**: 사용자 입력, 로딩 상태, 오류 메시지, AI 추천 결과 표시를 담당합니다.
- **Backend**: `/api/recommend` API를 통해 입력값을 검증하고 Gemini API를 호출하여 추천 결과를 반환합니다.

향후 기능을 추가할 경우 기존 API 구조를 유지하면서 기능별로 확장할 수 있습니다.

예를 들어 다음과 같은 기능을 추가할 수 있습니다.

- 여행지 상세 정보 조회 API 추가
- 추천 결과 저장 및 즐겨찾기 기능 추가
- 지도 API를 이용한 여행지 위치 표시
- 여행 일정 생성 기능 추가

기존 `/api/recommend` 인터페이스를 유지하면 새로운 기능을 추가하더라도 기존 여행 추천 기능에 미치는 영향을 최소화할 수 있습니다.

## 5. 사용 기술

| 구분         | 기술                    |
| ---------- | --------------------- |
| Frontend   | HTML, CSS, JavaScript |
| Backend    | Python                |
| AI         | Google Gemini API     |
| Python SDK | google-genai          |
| 환경변수 관리    | python-dotenv         |
| 배포         | Vercel                |

### Frontend 기술 역할

- **HTML**: 여행 날짜, 여행 스타일, 동반자, 추가 요청을 입력하고 AI 추천 결과를 표시하는 웹페이지의 구조를 담당합니다.
- **CSS**: 웹페이지의 레이아웃과 디자인을 구성하고 모바일 화면에서도 사용할 수 있도록 반응형 스타일을 적용합니다.
- **JavaScript**: 사용자 입력을 처리하고 `/api/recommend` API에 요청을 보내며, AI 추천 결과와 로딩 및 오류 상태를 화면에 표시합니다.

### 프레임워크 도입 검토

현재 프로젝트는 별도의 프론트엔드 프레임워크 없이 HTML, CSS, JavaScript를 사용하여
구현했습니다. 프로젝트 규모가 크지 않아 별도의 프레임워크 없이도 필요한 기능을 구현할 수
있도록 구성했습니다.

향후 사용자 기능과 화면이 증가할 경우 React와 같은 프론트엔드 프레임워크를 도입할 수 있습니다.

**장점**
- 컴포넌트 단위로 UI를 관리하여 코드 재사용성이 높아집니다.
- 화면 상태와 사용자 입력을 체계적으로 관리할 수 있습니다.
- 기능이 많아질수록 유지보수가 편리해질 수 있습니다.

**단점**
- 프로젝트 구조와 개발 복잡도가 증가할 수 있습니다.
- 별도의 빌드 환경과 패키지 관리가 필요합니다.
- 현재 프로젝트 규모에서는 불필요한 복잡성이 추가될 수 있습니다.

**예상 변경 범위**

React를 도입할 경우 기존 HTML 화면을 React 컴포넌트로 변경하고,
JavaScript의 사용자 입력 및 화면 상태 처리 부분을 React 방식으로 변경해야 합니다.

반면 Python의 `/api/recommend` API와 Gemini API 연동 구조는 그대로 유지할 수 있으므로
백엔드 변경 범위는 최소화할 수 있습니다.

## 7. API 구성

### POST /api/recommend

여행 정보를 전달하면 Gemini AI를 이용하여 여행지를 추천합니다.

### 요청 데이터

```json
{
  "date": "2026-08-25",
  "style": "자연 / 힐링",
  "companion": "가족",
  "request": "아이들과 함께 즐길 수 있는 여행지를 추천해주세요."
}
```

### 응답 데이터 예시

```json
{
  "recommended_city": "강원도 평창군",
  "weather": "8월 말 평창의 일반적인 날씨 설명",
  "events": [
    "대관령 양떼목장",
    "루지 체험",
    "워터파크"
  ],
  "reason": "가족 여행과 활동적인 여행 스타일을 고려한 추천"
}
```

### 오류 응답

필수 입력값이 누락되거나 서버에서 오류가 발생한 경우 오류 메시지를 반환합니다.

```json
{
  "error": "여행 정보를 입력해주세요."
}
```

## 8. 테스트 케이스

사용자 입력과 AI 추천 기능이 정상적으로 동작하는지 확인했습니다.

### ① 정상 입력 테스트

다음과 같이 여행 날짜, 여행 스타일, 동반자, 추가 요청을 입력했습니다.

```json
{
  "date": "2026-08-25",
  "style": "자연 / 힐링",
  "companion": "가족",
  "request": "아이들과 함께 즐길 수 있는 여행지를 추천해주세요."
}
```

**테스트 결과**

- 여행 정보 입력이 정상적으로 처리되었습니다.

- 추천 여행지와 날씨, 행사 및 관광 포인트, 추천 이유가 화면에 표시되었습니다.

### ② 필수 입력 누락 테스트

```json
  "date": "",
  "style": "",
  "companion": "",
  "request": ""
}
```

**테스트 결과**

- 필수 입력값이 누락된 경우 안내 메시지가 표시되었습니다.
- `"여행 정보를 입력해주세요."` 메시지를 확인했습니다.

### ③ 긴 입력 테스트

추가 요청에 긴 문장을 입력하여 AI 추천 기능이 정상적으로 동작하는지 확인했습니다.

**테스트 입력**


**테스트 결과**

- 긴 추가 요청이 정상적으로 처리되었습니다.
- Gemini AI가 입력 조건을 종합하여 여행지를 추천했습니다.
- 추천 결과가 웹페이지에 정상적으로 표시되었습니다.

### ④ API 오류 테스트

Gemini API 호출 과정에서 오류가 발생하는 상황을 가정하여 테스트했습니다.

**테스트 결과**

- API 오류 발생 시 사용자에게 오류 안내 메시지가 표시되었습니다.
- `"잠시 후 다시 시도해주세요."` 메시지를 확인했습니다.

## 9. 환경변수 설정

Gemini API Key는 보안을 위해 환경변수로 관리합니다.

`.env` 파일에 실제 API Key를 저장합니다.

```text
GEMINI_API_KEY=your_gemini_api_key
```

실제 API Key가 포함된 `.env` 파일은 GitHub에 업로드하지 않습니다.

GitHub에는 `.env.example` 파일만 제공합니다.

```text
GEMINI_API_KEY=your_gemini_api_key_here
```

### Vercel 환경변수 설정

배포 환경에서는 Vercel 프로젝트의 **Settings → Environment Variables**에서
`GEMINI_API_KEY`를 등록합니다.

등록 후 Production 환경에 적용되도록 설정하고, 환경변수를 변경한 경우
필요에 따라 재배포하여 변경사항을 적용합니다.

### API Key 유출 대응

API Key가 GitHub 저장소, 로그, 화면 캡처 등에 노출된 것으로 의심되는 경우 다음 절차에 따라 대응합니다.

1. 노출된 API Key를 즉시 폐기하거나 비활성화합니다.
2. Google AI Studio에서 새로운 API Key를 발급합니다.
3. Vercel의 **Environment Variables**에서 기존 키를 새로운 키로 교체합니다.
4. 변경된 환경변수를 적용하기 위해 서비스를 다시 배포합니다.
5. GitHub 커밋 및 로그를 확인하여 API Key가 추가로 노출된 곳이 없는지 확인합니다.
6. 이후 `.env` 파일이 Git에 포함되지 않도록 `.gitignore` 설정을 다시 확인합니다.

## 11. 배포

Vercel을 이용하여 실제 웹 서비스로 배포했습니다.

### Production

https://c-jade-nu.vercel.app

배포 후 실제 서비스에서 여행 정보를 입력하고 Gemini AI의 여행 추천 결과가 정상적으로 생성되는 것을 확인했습니다.

### 배포 문제 진단 및 재배포

배포 후 서비스에 문제가 발생할 경우 Vercel에서 배포 상태와 로그를 확인합니다.

1. Vercel 프로젝트의 **Deployments** 메뉴에서 해당 배포를 선택합니다.
2. **Build Logs**에서 빌드 과정에서 발생한 오류를 확인합니다.
3. AI 추천 기능에 문제가 있는 경우 **Runtime Logs**를 확인하여 API 실행 오류를 확인합니다.
4. Gemini API 호출 오류가 발생하면 Vercel의 **Environment Variables**에서 `GEMINI_API_KEY`가 정상적으로 등록되어 있는지 확인합니다.
5. 코드를 수정한 경우 GitHub에 변경사항을 push하여 새로운 배포를 진행합니다.
6. 필요한 경우 Vercel의 **Redeploy** 기능을 이용하여 다시 배포합니다.
